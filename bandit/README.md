# S3 · Bandit 策略学习（模拟环境里的"每次触达选哪条臂"）

> **边界一句话**：S1 回答「干预下去会发生什么」，S2 回答「谁值得干预」，**S3 回答「每个人只有一次触达机会、只看得到所选臂的结果时，如何边决策边学、能学多快」**。
>
> 为什么需要它：S2 是离线学习（先攒数据、再算效果、最后排序）；S3 是完全不同的处境——决策与数据同时发生，选了一条臂就永远看不到另外两条臂的反事实（**部分反馈**）。LinUCB 与线性高斯 Thompson 两大学派上场，对照 random / 三条固定臂 / oracle 上界：在线学了多少、学到的知识本身值多少，两层分开计价。
>
> 所以这一层 **不做**：离线先验注入与闭环迭代（留给 S4 接 harness）、疲劳与重复触达、预算 / 公平约束、真实世界的策略结论（模拟器只保证"方法可验证"，不保证"数字可迁移"）。

**本层决策（2026-10-05，已定稿）**
- 决策口径：**批量一次性决策**——每人一次触达机会，选一条臂，只观测所选臂的净奖励（部分反馈）；多色单遍人次出学习曲线；**无疲劳**（S1 v0 单次触达口径）。
- 算法：**LinUCB**（乐观主义）+ **线性高斯 Thompson**（概率匹配）；不做 ε-greedy（两种不确定性范式已足够）。
- 评测两层：**在线学习曲线**（含累计遗憾）+ **审计池冻结评测**（不再探索，只考知识）；对照 `random` / 三条 `fixed_*` / `oracle` 上界。
- **纯在线冷启动**：所有策略从零开始，无任何离线先验（闭环学习留给 S4）。

## 1. 数据流与模块

```
simulator.build_tables(...)        （S1，纯内存：真值 CATE 表）
        │  封装：一人 × 三臂净奖励矩阵；唯一反馈通道 observe(i, arm)
        ▼
bandit/
        ├── protocol.py   部分反馈世界：在线/审计切分、上下文基展开、observe 通道
        ├── policies.py   LinUCB + Thompson 线性高斯 + random / fixed_* / oracle
        ├── evaluate.py   在线学习曲线 + 审计冻结评测 + 每策略一行汇总
        ├── run_bandit.py CLI：全流程、落盘、_manifest.json、双跑一致性校验
        └── tests.py      冒烟与一致性测试（确定性 / 协议 / 无泄漏 / 端点 / 信号 / 边界）
        ▼
data/synthetic/bandit/             （合成数据，gitignored；可随时按种子重生成）
    ├── bandit_metrics.json        配置 / 世界口径 / 超参 / 每策略汇总（宽表 records）
    ├── bandit_curve.csv           在线学习曲线逐人次日志（全策略拼接）
    ├── bandit_summary.csv         每策略一行汇总（在线 + 审计）
    ├── bandit_audit.csv           审计池冻结评测逐人次日志
    └── _manifest.json             版本 / 模拟参数快照 / 输出指纹 / 双跑一致
```

**硬规则（反循环论证，都被 tests 测过）**
1. **策略只能通过 `world.observe(i, arm)` 拿到所选臂的净奖励**——真值矩阵是评测与 oracle 专用；关键不变量测试：把"未观测过的臂"奖励全部篡改后同种子重跑，**决策逐值不变**。
2. **上下文只由四件可观测状态派生**（与 S2 同一白名单）；z 标准化统计量**只用餐在线池**计算——审计池的信息不参与任何口径。
3. **按用户切分**（默认在线 70% / 审计 30%）：同一用户不会既参与学习又被冻结评测。
4. **deterministic**：同参同种子逐字节一致；CLI 默认**双跑一致性校验**，不一致拒绝落盘。
5. 产出是**合成环境上的方法验证**，不是真实世界的策略结论。

## 2. 部分反馈协议（本层的"世界规则"）

| 要素 | 口径 |
|---|---|
| 决策粒度 | 批量一次性：每人到访一次、选一条臂；**无疲劳、无重复触达**（S1 v0 单次触达；日粒度迭代留给后续版本） |
| 反馈可见性 | 只观测**所选臂**的净奖励（reward = 窗内增量 − 触达成本）；另外两条臂的反事实不可见 |
| 在线池 | 70%（4200 / 6000）——洗牌序即决策顺序，边决策边学 |
| 审计池 | 30%——按原始位置升序，冻结评测：策略只选不学（greedy，不再探索） |
| 上下文 | 四件可观测状态 → `logsq` 基：`[1, act_30d, log1p(silence), log1p(silence)², concentration, log1p(tenure)]`（宽 6）；在线池 z 标准化（std=0 保护为 1） |
| oracle | 逐用户真值 argmax（上帝视角上界，评测专用，不可部署） |

## 3. 策略与评测口径

**学习策略（统一线性假设：净奖励 ≈ θᵀx）**

| 策略 | 不确定性处理 | 超参（探针扫描锁定） |
|---|---|---|
| `linucb` | 每臂岭回归置信椭圆，选"上界最高"的臂：`θ̂ᵀx + α·√(xᵀA⁻¹x)` | `alpha 1.0`（0.5/1.0/2.0 三档在线均值几乎持平，取中档）· `ridge 1.0` |
| `thompson` | 每臂后验 N(θ̂, σ²A⁻¹)，采样 θ̃ 后贪心（探索自动衰减） | `sigma 1.0`（1.0/2.0/4.0 扫描中 1.0 跨种子略优）· `ridge 1.0` |

**基线**：`random`（均匀随机）／`fixed_control / fixed_rec / fixed_recall`（纯利用不求知）／`oracle`（上界参照）。
**冻结评估口径**：在线跑完后策略冻结——LinUCB 用后验均值（去 bonus），Thompson 用后验均值（不采样）；部署时"不再探索"的诚实口径。

**评测两层**
1. **在线层**（逐人次日志）：`head20 / tail20`（前 20 步 vs 后 20 步均值 = 学习信号）、`cum_regret = Σ(oracle_reward − reward)`、`reward_vs_oracle_frac`、三臂占比。
2. **审计层**（冻结日志）：审计均值、人均遗憾、`audit_vs_oracle_frac`——把"探索的运气"与"学到的知识"分开计价。
3. 遗憾口径：`regret = oracle_reward − reward ≥ 0`；oracle 恒为 0 上界（tests 锁死端点）。

## 4. 结果（离线默认人口，6000 人 × 14 天，seed 13，在线 4200 / 审计 1800）

先说一句背景：默认人口是**沉默为主**的社区；三臂真值均值 `control 0.000 / rec −0.341 / recall +0.993`——**rec 臂整体为负**（呼应 S2：推荐臂撑不起成本），价值集中在召回臂。

**在线 → 审计（净奖励口径，单位 = 事件当量）**

| 策略 | 在线均值 | head20 | tail20 | 累计遗憾 | 审计均值 | 审计 / oracle | recall 占比 |
|---|---|---|---|---|---|---|---|
| `linucb` | +1.081 | −0.025 | +1.150 | 1422 | +1.119 | **0.804** | 76% |
| `thompson` | +1.084 | +0.225 | +1.150 | 1408 | +1.119 | **0.804** | 76% |
| `random` | +0.192 | +0.650 | +0.025 | 5157 | +0.247 | 0.178 | 34% |
| `fixed_control` | 0.000 | 0.000 | 0.000 | 5962 | 0.000 | 0.000 | 0% |
| `fixed_rec` | −0.346 | −0.500 | +0.100 | 7416 | −0.328 | −0.236 | 0% |
| `fixed_recall` | +1.000 | +0.750 | +0.700 | 1760 | +0.974 | 0.699 | 100% |
| `oracle` | +1.420 | +1.100 | +1.275 | 0 | +1.393 | 1.000 | 40% |

**基与超参扫描（同种子，只列学习策略）**

| 基 | 策略 | 在线均值 | 审计均值 | 审计 / oracle |
|---|---|---|---|---|
| raw | linucb(α=1) | 1.074 | 1.081 | 0.776 |
| **logsq** | linucb(α=1) | **1.081** | **1.119** | **0.804** |
| raw | thompson(σ=1) | 1.056 | 1.080 | 0.776 |
| **logsq** | thompson(σ=1) | **1.084** | **1.119** | **0.804** |

LOG 变换（沉默 / 资历右偏）把两个学习器都抬高约 0.03–0.04 审计均值——**上下文表示和算法一样重要**。

**读出来的四件事**
1. **学习确实发生**：head20 ≈ 0 → tail20 ≈ 1.15（前 20 步还在试错，后 20 步已贴着 oracle 走）；在线均值 +1.08 是 random（+0.19）的 **5.6 倍**，也比最好的固定臂 `fixed_recall`（+1.00）高约 8%。
2. **知识本身值钱（审计冻结）**：不再探索后仍有 +1.119 = oracle 的 **80.4%**（固定 recall 69.9%、random 17.8%）——收益不是探索的运气，学到的知识可迁移到没见过的用户。
3. **探索的代价可控**：累计遗憾 1408–1422，≈ oracle 总量（1.411 × 4200 ≈ 5926）的 **24%**；两条策略差异 < 1%，说明这个任务上"乐观主义"与"概率匹配"打平。
4. **结构发现与 S2 互证**：rec 臂真值均值为负 → 学习策略几乎不选 rec（占比 3.9%），oracle 也只对 4.9% 用户选它；`oracle` 的 recall 占比只有 40%——**"谁适合什么"是因人而异的**，而这 40% × 完美选择正是 80% 与 100% 之间剩下那 20% 的来源。

## 5. 运行与产出

```bash
# 在仓库根目录执行
python -m bandit.run_bandit --users 6000                # 默认：有 L2 用拟合人口 + 双跑校验
python -m bandit.run_bandit --no-fit --users 6000       # 强制默认人口（离线可复现路径）
python -m bandit.run_bandit --policies linucb,random --no-verify   # 子集、跳过校验（快路径）
python -m bandit.tests                                  # 测试（也可 pytest bandit/tests.py）
```

CLI：`--users --days --window --seed --audit --policies --alpha --ridge --sigma --out --features --no-fit --no-verify`。
退出码：参数无效 `2`；双跑不一致 `3`（拒绝落盘）。

产出（默认 `data/synthetic/bandit/`，不入公开仓）：见 §1 文件清单；`_manifest.json` 冻结版本 / 模拟参数快照 / 世界口径 / 超参 / 输出指纹与行数。

## 6. 与上下游的接口

| 上下游 | 用法 |
|---|---|
| S1 模拟器 | `build_tables` 的 `sim_effects.reward` 列即每人 × 三臂净奖励；本层封装成 `BanditWorld`（`observe` 是唯一反馈通道） |

## 7. 已知局限（诚实清单）

1. **无真实标签**：真值来自模拟器——价值在"方法验证"（无泄漏、可复现、两层评测），不在"业务数字"。
2. **批量口径**：无疲劳、无重复触达、奖励即时可见（无延迟反馈）；日粒度在线迭代是后续版本的事。
3. **线性假设**：S1 的效应形状（门槛、钟形）非线性；线性策略的上限即"线性可解释部分"，与 oracle 的差距是表示能力的余量，不是 bug。
4. **无约束**：不考虑预算、曝光配额、公平性（每条臂成本已入净奖励，但无全局约束）。
5. **超参未做完整搜索**：三档扫描后锁定，非调优终点。
6. **审计池有限**：1800 人冻结评测，末位数字有抽样波动；学习信号已跨种子（7 / 11 / 13）复核稳健。
